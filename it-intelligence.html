Application boundaries

IT Intelligence
has its own scope.

IT Intelligence focuses on delivery lifecycle, traceability, knowledge, evidence, approvals, and proposed agent orchestration. Atlas addresses capacity and portfolio decisions. The Intake Agent handles request preparation and routing. They are three separate applications.

The source documents include intake and portfolio concepts in the target architecture. Those concepts describe capability or data relationships; they do not make the separate Atlas and Intake Agent applications modules of IT Intelligence. Any cross-application integration requires its own defined contract and validation.

AI architecture · Decisions and safeguards

Connect the evidence.
Control the action.

IT Product Delivery Intelligence is a target-state design. Its technical value lies in connecting approved scope, delivery evidence, and decision owners without letting an agent authorize its own work.

Keep source ownership clear

Monday.com remains authoritative for execution records; SharePoint holds versioned documents. The proposed project model links their identifiers rather than replacing either source.

Separate advice from execution

An agent prepares an evidence-linked proposal. A named reviewer approves it. A separate command checks the source version, avoids duplicate execution, and reads back the result.

Make recovery part of the design

A changed source requires fresh review. A partial failure needs reconciliation. Control-function stops remain authoritative even when a person approves a proposal.

Basis: the data-modeling guide, workflow inventory, agent control map, and target-state playbooks. The local command demonstration uses synthetic records and makes no live writes.

What I would validate first

Trust the inputs.
Then test the intelligence.

Source quality

Required fields, stable identifiers, board mappings, timestamps, and reconciliation before executive forecasts.

AI behavior

Retrieval permission tests, source coverage, unsupported-answer handling, approval boundaries, and tool failures.

Decision rights

IT Demand owns classification; functions own domain approvals. Control-function hard stops remain authoritative.

Business value

Baseline reporting effort and intake time; compare measured outcomes after the pilot. Separate released capacity from cash savings.

Build and Buy have the strongest grounding in the supplied operating materials. Dedicated Automate, Integrate, and Decommission lifecycles are recommended extensions requiring formal adoption. The Microsoft-aligned technical stack is a target-state option, not an implementation credential.
